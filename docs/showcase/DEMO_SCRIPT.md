# 演示脚本（30–60 秒）

面向录制屏幕演示或现场路演。所有画面均为项目**已实现**的真实界面，
数字来自 `docs/screenshots/` 中保存的真实运行截图。

> **录制前必读**：菜单和价格随门店、时段实时变化。脚本里写的金额是**截图那一次**的真实结果，
> 你录的时候大概率不一样。**不要照念金额**，按「录制时怎么处理数字」一节的规则来。

---

## 一、演示前准备

| 项 | 做法 |
|---|---|
| 启动 | `npm run dev`，打开 `http://localhost:3000` |
| 门店 | 选一个当前时段营业、菜单比较全的门店（首页「门店与偏好」下拉可切换） |
| 环境变量 | 填入真实 `MCD_MCP_TOKEN`；**不要**填 `AI_API_KEY`（默认规则模式，与截图一致） |
| 浏览器 | 缩放 100%，窗口宽 ≥ 1280；录屏 1440×900 最贴近现有截图 |
| 关闭 | 关掉无关标签页、系统通知、浏览器书签栏 |
| 备用 | 若现场网络不通，切到 `/demo`（冻结快照，不联网），并**口头说明这是演示数据** |

## 二、45 秒主版本（推荐）

| 时间 | 画面 | 操作 | 口播 |
|---|---|---|---|
| 0–5s | 首页首屏 | 鼠标停在输入框 | 「中午只有 25 块，想吃鸡肉，还不要太辣。这种时候最纠结。」 |
| 5–9s | 输入框 | 输入：`今天只有 25 元，想吃鸡肉，不要太辣` | 「一句话说清楚就行。」 |
| 9–12s | 结果区 | 点「帮我选这一顿」，等待 | 「它先去查这家店今天的真实菜单。」 |
| 12–20s | 「我理解到的需求」卡片 | 鼠标依次划过：午餐 / ¥25.00 / 鸡肉 / 辣（已过滤） | 「先把理解结果摊开：午餐、上限 25、要鸡肉、辣的已经过滤掉了。**理解错了你能一眼看见。**」 |
| 20–30s | 三份方案 | 停在首选卡片，指一下价格右侧的「官方核价」 | 「三份方案，每份这个价格都不是估的，是调官方算价接口逐个核对过的。首选这份**（读屏上的金额）**，扣掉之后还剩多少也直接写出来。」 |
| 30–38s | 继续下滑 | 展示备选两份 | 「省钱优先、满足优先，三种取向各一份，不用自己算。」 |
| 38–48s | `/budget` 页 | 点顶部「长期预算」，拖到 Meal Impact 面板 | 「换个问题：这笔钱花掉，这个月还剩多少？填一个金额，它直接告诉你吃之前日均多少、吃之后日均多少。」 |
| 48–55s | 概览区 | 指「消费进度 8% ／ 时间进度 71%」 | 「比余额更有用的是这个：钱花得比时间慢，还是快。」 |
| 55–60s | 收尾 | 回到首页 | 「只读查询，不下单不领券，数据只在你自己的浏览器里。MIT 开源。」 |

**口播总字数约 190 字**，按每秒 4 字计算约 47 秒，留出点击和加载的余量，实测落在 50–60 秒。

## 四、60 秒技术版（面向开发者评审）

在 45 秒版基础上，把 20–30s 的「三份方案」一段扩写为技术细节：

> 「候选不是随便排的。菜单拉回来先做角色分类——酱料、单点饮料、甜品、周边、多人餐全剔除，
> 因为它们不算一顿饭。剩下的组合再逐个调 `calculate-price` 核价，超预算就换下一个。
> 单次请求最多核 12 个组合，这是为了保住响应时间。
> 结果排序用四维评分加权，三种取向权重不同：省钱优先把价格权重压到 0.78，满足优先把口味提到 0.52。
> 候选不足时返回实际数量并告警，**不凑数**。」

配套可展示的硬指标（**只念真实值**）：

| 指标 | 值 |
|---|---|
| 真实使用的 MCP 工具 | 3 个，全只读 |
| 单元测试 | 474 项，全部通过 |
| 真实接口集成测试 | 26 通过 / 3 条件跳过 |
| 浏览器端到端断言 | 69 项，0 失败 |
| 线上部署 | **无**（本地运行） |

## 五、录制时怎么处理数字

> 这一节是为了防止「照着旧截图念金额」和「界面显示的不一样」的尴尬。

1. **价格类**：一律读屏幕上当下显示的金额，不要读本文件里的数字。若必须提前写稿，
   用「**（读屏）**」占位，录完再补。
2. **比例类**（如「占预算 64%」「消费进度 8%」）：随输入变化，同样读屏。
3. **固定类**（餐次、排除项、按钮名、页面名）：可以写死，它们不随数据变。
4. 若录制时某家店某时段菜单为空，界面会给出空结果和原因——**这本身是可讲的点**：
   「查不到就说查不到，不用估算价格凑一个出来。」
5. 全程不要出现任何真实 token、手机号、个人姓名、门店账号信息。

## 六、常见失误

| 失误 | 后果 | 避免方式 |
|---|---|---|
| 把 `/demo` 说成实时查询 | 属于不实陈述 | 提到 `/demo` 必须同时说「演示数据」 |
| 说「接入了大模型」 | 与当前状态不符 | 规则模式下只说「规则解析」，或点开徽标让人看 |
| 给出「在线体验地址」 | 项目未部署 | 只说 GitHub 仓库地址 |
| 念截图里的旧价格 | 与屏幕不符 | 读屏，不背稿 |
| 演示前没确认门店营业 | 空结果，尴尬 | 开录前先跑一次查询 |
