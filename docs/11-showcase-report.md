### 5.1 关于第一次集成测试失败

失败形态是 `McpClientError: fetch failed`，出现在 `findStores` 的连接阶段。
独立用 curl 验证端点 `https://mcp.mcd.cn`：不带鉴权头返回 **403 + `{"code":"0001","msg":"系统错误"}`**，
说明端点本身可达，不是域名解析或服务下线。

立即重跑同一条命令，得到 26 通过 / 3 跳过，与历史记录完全吻合。
**判定为瞬时的测试进程出网失败，不是代码缺陷、也不是接口变更。**

处理方式：如实记录两次结果，不隐藏第一次；README 也不因此改动数字，而是补上复跑日期与
E2E 未重跑的说明。

### 5.2 为什么 E2E 没重跑

E2E 需要额外两步前置：另起 `next start -p 3100` 生产服务，以及用 CDP 驱动本机 Chrome；
脚本本身在仓库外（`../_e2e-005.mjs`）。本次改动**只涉及 Markdown 文档**，
未触及任何 `.ts/.tsx`、样式或 API，E2E 断言的对象没有变化。

### 10.1 关于「相对链接在 GitHub 上是否真的可点」

本地脚本只验证了**文件存在性**，不等于 GitHub 渲染后链接可点。两者的差异点在于大小写与 URL 编码。
为此额外确认了三处最容易出问题的引用：

| 引用 | 风险 | 实际 |
|---|---|---|
| `docs/screenshots/005-*.png` | 文件名含连字符与小写，路径层级 `docs/screenshots/` | 远端 tree 中存在同名 blob，大小写一致 |
| `docs/showcase/` | 目录链接（GitHub 支持目录跳转） | 4 个文件均在同一目录下 |
| `MCP_INTEGRATION.md` / `workbuddy.md` | 仓库根目录文件 | 远端 tree 中存在 |
